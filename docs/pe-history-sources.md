# 負 EPS 的歷年本益比顯示

有明確負值依據的歷史期間，以 0 的水平虛線表示；hover 顯示「該期間 EPS 為負，不予顯示」。0 僅供圖表定位，並非有效估值，不加入市場平均或中位數。

月快照格式保持前四欄 `[pe, pb, dy, price]` 不變，可選第五欄 `"negative_eps"` 表示已確認原因。重建個股檔後是 `[ym, pe, pb, dy, price, reason]`。正常 P/E 優先，未確認的 null 維持原有濾除處理。前端亦支援明確的負 P/E 數值。

資料正規化只在來源提供負 P/E 數值時保留 `peReason`，每日快照、回補與個股重建均會傳遞此原因。

## 嚴格判定與歷史資料範圍

現有歷史檔只保存正值或 null，沒有保存 EPS 或空值原因。現行官方端點通常以空白或 N/A 表示不適用，這項程式修改**不會自動把這些空值認定為負 EPS**。採嚴格判定：日期或原因無法確認的舊資料保留原樣，不按一般公告時程推估，也不因功能上線而批次補 0。日後只有取得與各歷史交易日期對應、可驗證的近四季 EPS 或明確負值原因資料，才能標記該期間。

[證交所計算說明](https://www.twse.com.tw/zh/trading/historical/bwibbu-day.html)指出，EPS 為 0 或負數皆不計算本益比，財報未申報或未齊全也可能不計算。因此不得把所有 null、N/A 或 0 一律標為負 EPS；也不得拿最新 EPS、單季 EPS 或年度累計 EPS 回填所有歷史月份。

## 全市場：以交易所當日財報年季核對 EPS

`scripts/build_pe_periods.py` 對全部歷史月快照的**精確交易日期**查詢上市與上櫃官方估值資料。只在回應日期與快照日完全相同、來源 P/E 為空值，且該股票有明確「財報年/季」欄位時，保存核對依據至 `pe_report_periods.json`。沒有年季欄位的舊資料不按財報公告期限猜測；股票、日期與資料來源不能互相替代。

接著向[公開資訊觀測站財務比較 E 點通](https://mopsfin.twse.com.tw/)查詢單季 EPS（`compareItem=EPS`、`quarter=true`），以明確公司身分與合併報表標記 `C` 配對。只採四個連續季度的有限數字，合計小於 -0.02 元，才可標為 `negative_eps`；零、接近零的四捨五入不確定值、缺季或個別報表皆不採用。單季轉盈但四季合計虧損仍可標記，單季虧損而四季合計為正則不可。EPS 原始季度數字、來源與查詢時間保存至 `pe_eps.json`，不重算 P/E 或改動原始月估值。

這條路徑使用交易所**在當日明確列出的適用財報年季**確認日期，不依最新 EPS 反推所有月份，也不必推測同日財報是在盤前還是盤後。季度 EPS 是查詢時官方資料庫提供的數字，可能包含官方重編；此功能只核對負值方向，並不還原歷史時點所有財報版本。可驗證的日期、年季或 EPS 不足時，保留原處理。

每日更新先收集新快照的年季，再重建全部個股歷史。完整查核過的舊日期使用快取；失敗或日期不符會重試，不會憑空補 0。EPS 每七日刷新，遇到交易所出現尚未快取的新年季則提前刷新。此規則適用所有有相同證據的股票；興櫃或其他來源未提供相應證據時仍保留空值。

瑞基（4171）最新交易日 2026-10-08 的櫃買資料明確列為 `115Q2`；官方合併單季 EPS 為 2025Q3 -0.65、2025Q4 0.05、2026Q1 -0.09、2026Q2 -0.07，四季合計 -0.76 元，因此最新月份會顯示虛線 0，提示「該期間 EPS 為負，不予顯示」。
