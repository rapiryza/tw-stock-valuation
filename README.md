# 台股估值與成長率追蹤

台灣股市 **上市／上櫃／興櫃** 三個板塊的估值與成長指標，每交易日自動更新，
以 GitHub Pages 呈現。另有一個 **美股** 分頁，資料取自 SEC EDGAR 官方開放資料。

網站：<https://roseamyclara.github.io/tw-stock-valuation/>（頂欄可切換台股／美股）

## 指標

| 指標 | 說明 |
|---|---|
| **P/E** 本益比 | 上市取自證交所、上櫃取自櫃買中心的官方計算值。興櫃沒有 — 見下方說明 |
| **P/S** 股價營收比 | 自行計算：市值 ÷ 近十二個月營收。官方未提供此欄位 |
| **P/B** 股價淨值比、殖利率 | 上市／上櫃取自官方 |
| **月營收年增率** | 最新月份營收與去年同月比較 |
| **累計營收年增率** | 本年度累計營收與去年同期累計比較 |
| **獲利成長率** | 最新一季累計的營業利益、稅後淨利、EPS 與去年同期比較 |
| **業外占稅前淨利／營業利益%** | 營業外收入及支出 ÷ 稅前淨利、÷ 營業利益（年初至今累計）；分母 ≤ 0 時留白 |
| **外匯損益占淨利%** | 財報附註「外幣兌換利益（損失）」÷ 歸屬母公司淨利；取自官方 iXBRL，由 `build_fx_gains.py` 每日漸進讀取 |

市場層級的 P/E 與 P/S 由成分股加總計算（總市值 ÷ 總淨利、總市值 ÷ 總營收），
三個板塊口徑一致，也不受個股極端值影響。

## 資料來源

全部來自政府公開的官方開放資料，免申請、免金鑰：

- **臺灣證券交易所 OpenAPI** — <https://openapi.twse.com.tw/>
- **證券櫃檯買賣中心 OpenAPI** — <https://www.tpex.org.tw/openapi/>

月營收另讀取 MOPS 官方提供的月份 CSV：
`https://mopsov.twse.com.tw/nas/t21/{sii|otc|rotc}/t21sc03_{民國年}_{月}.csv`。
每次抓最近兩期，按公司比較月份及出表日期，合併 OpenAPI 與前次成功資料；
OpenAPI 整批月報可能落後於當期申報，不能只以請求成功判定已更新。
尚未公告、缺列或來源失敗時保留可用舊期，來源狀態與月份分布寫入 `meta.json`，
每筆營收附來源及出表日期（不是公司申報時間）。畫面顯示各股營收月份。
不逐家公司爬取查詢頁；CSV 可能在月初尚未產生，並不保證即時。

```

    │
    ├─ scripts/build_snapshot.py    每交易日：抓最新報價、本益比、月營收、損益表
    ├─ scripts/rebuild_history.py   每月：重建各年度歷史與個股頁資料

    │
```

## 資料的邊界

這些是官方開放資料本身的限制，不是程式沒做到：

**興櫃沒有本益比與獲利成長率。** 證交所與櫃買中心都沒有發布興櫃公司的綜合損益表，
沒有淨利與 EPS 就算不出本益比。但興櫃有月營收，所以 **P/S 算得出來** ——
對還沒穩定獲利的公司，股價營收比本來就比本益比更堪用。

**P/S 在年度中是推估值。** 月營收公布的是「今年累計」與「去年同期累計」，
但沒有「去年全年」。網站累積滿一個十二月之後就會轉成精確值；在那之前，
以去年同期的季節比例推估剩餘月份，並在數字旁標示「估」。

**歷年 P/S 已支援官方歷史重建。**
以當時股價、當時發行股數及完整 12 個月營收，自 2013 年起回補上市、上櫃與興櫃。
個股實際起點依掛牌及資料完整度不同；2012 營收取 2013 年表內去年同月比較欄。
2013 年以前舊表口徑不同，未直接混接。重建資料可能含事後更正，並非當時可得資訊的回測序列。
2026 年 8 月起原始快照仍保留「實際／估算」標記，每日更新逐月累積。
詳見 [來源、計算方式與限制](docs/ps-history-sources.md)。

**股數的取得方式。** 上市取自公司基本資料的「已發行普通股數」；
上櫃與興櫃在缺少該欄位時，以「實收資本額 ÷ 面額 10 元」回推。
少數面額非 10 元的個股，市值與 P/S 會有偏差。

**證交所 OpenAPI 對連續請求敏感。** 短時間連打二十幾個端點會被流量保護擋下
（回一頁 HTML 而非 429）。程式對該主機設了 4 秒最小間隔，並會辨識這個攔截頁後退避重試。

本專案僅整理公開資料，不構成任何投資建議。

## 內部人持股增減（docs/data/insider_flows.json）

| 項目 | 口徑 |
|---|---|
| **總持股** | 只用證交所 IRB110：董事監察人實際持有＋經理人實際持有。不含百分之十以上大股東欄（常與法人董事重複）、法人代表人分戶、保留運用決定權信託 |
| **單月增減** | 公開資訊觀測站「內部人持股異動事後申報表」的集中市場買進−賣出，加上經理人以其他原因取得的員工股／RSU（另行標示） |
| **剔除** | 除權配股、股票分割、贈與、轉讓、信託、內部人之間移轉、董監經理人就任／解任造成的名單變動 |
| **轉讓申報** | 每日「事前申報」只是預定，不是成交，不計入持股增減 |

- 同一人兼任多職、同一法人董事派多位代表人，都只算一次；歸戶方式與 IRB110 相同，因此每月明細加總會與 IRB110 逐股核對（`verified`）。
- 「選任時持股」與目前持股的差距是任期內累計，不當成單月增減。
- 申報明細一家一份，由「內部人持股申報明細」workflow 每天三次漸進補抓（`fetch_insider_detail.py`）；尚未取得明細的月份，單月增減留白，不以總額差代替。
- 口徑測試以官方實際資料為樣本：`python -m unittest test_insider_holdings`（台積電贈與與人事異動、圓祥法人董事雙代表人與 RSU、寶雅股票分割、鴻海大股東）。

## 業務標籤（docs/data/tags.json）

表格的「業務標籤」欄顯示這家公司實際在做什麼（例如 6170 統振 →
外籍移工／匯款／電信加值），搜尋框也會比對標籤。

**這份標籤是人工整理的，不是官方資料。** 官方開放資料只有約 30 類的「產業別」，
沒有這種顆粒度；證交所與櫃買中心的產業價值鏈資訊平台有，但其使用條款禁止未經
書面同意重製與散布。因此標籤由人工撰寫，涵蓋 2,342 檔中的 1,423 檔（60%），
其餘（多為興櫃與小型股）在無把握時一律留空，網站上退回顯示官方產業別，
並以虛線外框區隔來源。

格式很單純，要修改或補充直接編輯這個檔案即可：

```json
{ "6170": ["外籍移工", "匯款", "電信加值"], "2330": ["晶圓代工", "先進製程", "CoWoS"] }
```

每日更新流程不會動到這個檔案。

## 美股頁（docs/us.html）

網站有第二個分頁 `us.html`，頂欄可以在台股／美股之間切換。

**財報全部來自 [SEC EDGAR 的 XBRL frames API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)**，
一樣是官方開放資料、免申請免金鑰。用 frames 而不是 companyfacts 的原因：
companyfacts 一家一支 API，五千多家要打五千多次；frames 是「一個會計科目 ×
一個期間 → 全市場」，抓完整份快照只要二十幾次請求。

| 指標 | 算法 |
|---|---|
| **本益比** | 股價 ÷ 近四季 EPS（TTM） |
| **股價營收比** | 市值 ÷ 近四季營收 |
| **淨值比** | 市值 ÷ 股東權益 |
| **季營收／淨利年增率** | 最近一季 vs 去年同季 |
| **毛利率、淨利率** | 近四季合計 |
| **市值** | 股價 × SEC 申報股數；沒有股數才用報價來源給的市值 |

**TTM 有兩條算法**，這是被 SEC 資料的形狀逼出來的。第四季多數公司不單獨申報
（數字併在 10-K 裡），所以 `CY2025Q4` 這種季度框幾乎是空的 —— 一年裡有大半時間，
「最近四季相加」會讓九成公司算不出 TTM（實測 4,812 家只有 170 家有 EPS）。因此：

1. 四季齊全 → 直接相加，最精確；
2. 湊不齊 → **上一個完整年度 ＋ 今年至今 － 去年同期至今**；
3. 兩條都湊不齊 → 留白。

跟台股頁刻意不一樣的地方，都是制度差異不是偷懶：

- **沒有月營收年增率。** 美國公司不公布月營收，只有季報，所以改用季度年增率。
- **沒有殖利率。** 要自己從股利科目推，XBRL 裡這塊很雜，先不做。
- **沒有漲幅排行與族群。** 那需要每日收盤價的歷史，目前只存最新報價。

### 美股資料的邊界

- **SEC 的季度資料框只收會計季與日曆季對齊的公司。** 九月結算那種非日曆年度的
  公司會被漏掉，這是 frames API 本身的限制。
- **營收的會計科目不統一。** `RevenueFromContractWithCustomerExcludingAssessedTax`
  涵蓋約 2,555 家、`Revenues` 約 1,926 家（2025Q2 實測），程式依序比對四個常見
  科目取聯集，仍有部分公司對不上。
- **SEC 不發布股價。** 收盤價與市值走 Nasdaq 的上市股票清單端點，一次請求
  就拿回三大交易所全部約 7,100 檔的前一交易日收盤價與市值，這是全流程唯一的
  非官方來源。只在店頭市場（OTC）交易的公司這裡沒有，估值比率會留白。
  若要維持「全部資料都來自官方」，用 `--no-prices` 跑，本益比／股價營收比／
  淨值比會留空，但 EPS、營收年增、利潤率仍然有。
- **不要用逐檔抓報價的來源。** 早期版本走 Stooq，一檔一個請求，四千多次會被
  對方整批擋掉（實測 4,812 檔一檔都沒回）。`--prices stooq` 還留著當備援，
  但有限速也只取前 600 檔。

### 美股的業務標籤（docs/data/us/tags.json）

**不是人工整理的，是自動反推的** —— 依「這檔股票被哪些主題型 ETF 持有」推出
標籤，再用相對大盤權重過濾掉純粹當底倉的權值股（沒有這道過濾，MSFT 會因為
每檔主題 ETF 都拿它當底倉而被貼上「電動車、自駕」）。

它抓的是市場對這家公司的歸類，不是公司自己的業務描述，涵蓋 492 檔、35 種標籤，
顆粒度比台股頁的人工標籤（1,423 檔、1,699 種）粗得多。要加標籤就是加 ETF。

## 登入分析與審計後台（docs/admin.html）

網站可選擇性開放會員登入（Supabase Auth），後台提供三個功能：

1. **登入地理位置追蹤**：每次登入記錄 IP，由伺服器端（Edge Function `record-login`）從連線標頭取得，前端無法偽造；再用 ipwho.is 解析成國家、城市與經緯度，顯示在列表與地圖上。
2. **登入頻率統計**：指定期間（過去 7／30／90 天或自訂）每位使用者的登入次數、平均登入間隔、期間最後登入與歷史最後登入（資料庫函式 `login_frequency`）。
3. **IP 排除名單**：後台可新增單一 IP 或 CIDR 網段（例如公司內網）。名單內的登入仍會記錄，但不計入列表統計、地圖與頻率報表；排除在查詢時比對，所以新增或刪除後歷史統計會立即重算。

只有 `login_admins` 資料表內的帳號能讀取紀錄（Row Level Security）。登入視窗會告知使用者登入時會記錄 IP 與大略地點。

**啟用步驟**

1. 建立 Supabase 專案，在 SQL Editor 執行 `supabase/migrations/20261020000000_login_analytics.sql`。
2. 部署 Edge Function：`supabase functions deploy record-login`（或在 Dashboard 的 Edge Functions 貼上 `supabase/functions/record-login/index.ts`）。
3. 在 `docs/assets/supabase-config.js` 填入 Project URL 與 anon public key（不要放 service_role key）。
4. 到 Authentication → URL Configuration 把網站網址加入 Site URL／Redirect URLs。
5. 註冊自己的帳號後，在 SQL Editor 執行：
   `insert into public.login_admins (user_id) select id from auth.users where email = '你的 email';`

未填設定檔時，登入按鈕與後台都不會出現，網站其他功能不受影響。

## 什麼會自動更新，什麼不會

「每日更新」workflow 在**台北時間 13:37、14:37、15:07、16:37、19:23**（週一至五）分批抓取。
13:37 開始嘗試上市／上櫃收盤資料，14:37 在盤後定價交易後補抓，15:07 再補抓；
16:37 涵蓋較晚的興櫃盤後統計，19:23 保留作晚間備援。每輪沿用三市場一起更新的流程，
早期輪次的興櫃仍可能是盤中資料；各 API 公布時間不同，不能將執行時間視為資料已齊的保證。

美股在**美東週一至五 16:17、17:17、19:17**抓取，使用 America/New_York 自動處理夏令／冬令。
台北時間為週二至六：夏令 04:17、05:17、07:17；冬令 05:17、06:17、08:17。
首輪於正常收盤後 17 分鐘開始，後兩輪補抓 Nasdaq 清單端點延遲；不是追蹤延長時段交易。
假日仍可能跑到上一交易日資料。月營收、財報與估值各自依來源公布進度更新。

所有分鐘均避開 :00、:30。GitHub Actions 是盡力排程，仍可能延遲或漏排；
抓取、計算及 Pages 發布亦需時間，因此這是收盤後分批更新，無法保證來源一公布便即時上線。
實際執行時間請見 Actions，資料日期請見網站標示。

| 資料 | 更新頻率 | 說明 |
|---|---|---|
| 股價、市值、P/E、P/B、殖利率 | 每交易日 | |
| P/S | 每交易日 | 股價變動就會變 |
| 漲幅排行（1／5／10／30 日）、族群 | 每交易日 | |
| 每日收盤價 `prices.json` | 每交易日 | 保留最近 70 個交易日 |
| 月營收年增率、累計年增率 | 每月 | 每天檢查，官方約每月 10 號發布後隔天就會更新 |
| 獲利數字、獲利成長率 | 每季 | 每天檢查，財報發布後跟著更新 |
| 各年度估值走勢 `history/` | 每交易日刷新當月、跨月自動新增 | |
| 個股歷史頁 `stock/` | 每交易日重建，內容實際上每月變一次 | |
| **業務標籤 `tags.json`** | **不會自動更新** | 人工整理，要改直接編輯該檔 |
| 美股 `data/us/` | 每交易日 | 由「美股每日更新」workflow 產生，美東 16:17、17:17、19:17 |
| 美股標籤 `data/us/tags.json` | **不會自動更新** | 由主題 ETF 持股反推，要更新得重跑產生器 |

興櫃的 5／10／30 日漲幅是從本站開始收集後逐日累積的（官方沒有整批的興櫃歷史
每日行情端點），累積滿對應天數後才會出現。

### 個股價格表現

個股表的「漲跌幅%」表頭可切換五年、一年、今年迄今、三個月、一個月、一週；
點標題排序，切換期間會沿用目前排序條件。手機版使用篩選列的期間選單。
另顯示距離 52 週最低／最高成交價的百分比。

- 期間採日曆週、月、年；基準日休市時取之前最近有交易的收盤價（最多回溯 14 日）。
- 今年迄今以前一年最後交易日為基準；價格未還原權息，不等於含息總報酬。
